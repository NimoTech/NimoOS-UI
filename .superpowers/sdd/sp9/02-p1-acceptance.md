# 第二轮:第一轮那 4 个「保存配置失败」已修(2026-07-31)

**坐标**:New-UI `master` `b9a86b1 → bcb991b`(fix `219b854` + 补提 P1 计划书 `bcb991b`)。Service 侧零改动。
**任务门**:`pnpm test` **289 文件 / 2190 例全绿**(+1 文件 +1 例 = 新增的配置守卫)、`vue-tsc` 0 错、`vite build` 通过。

## 根因(不在 P1 的代码里,在 dev server)

`@nimotech/nimoos-service` 是 `file:../NimoOS-Service` 依赖,pnpm 把它的 `dist` **硬链**进 `.pnpm` 目录,
所以 Vite 当普通 node_modules 依赖**预打包**进 `node_modules/.vite/deps/`。
预打包缓存的失效判据是 **lockfile / vite config / 依赖版本号,不看依赖内容**,而这个包版本号恒为 `0.0.1`
—— P1 把 `sys` 域从 3 个方法扩到 24 个、`pnpm build` 过了,但缓存**没失效**。

实证(修之前,从跑着的 dev server 上抓的):
`GET /app/node_modules/.vite/deps/@nimotech_nimoos-service.js` 里 `sys` 域只有
`/sys/utilization`、`/sys/hardware`、`/sys/version` 三条路径 —— 正是 P1 之前的基线。
于是浏览器里 `service.sys.toggleUsbAutoMount` / `editServerPort` / `setSSLConfig` / `getSSLConfig`
全是 `undefined`,调用即 `TypeError`,被各行的 `catch` 吞成「保存配置失败」。
四个报错点(USB 行 / WebUI 端口行 / HTTPS 开关 / 进 developer 页)是**同一个根因**。

**为什么三道门全绿也没抓到**:vitest 和 `vite build` 都直读 `node_modules` 里的真实文件
(与 `../NimoOS-Service/dist` 同 inode,永远是新的),**只有 dev server 有这层缓存**。
叠加「浏览器自查 0/16、没人看过这个屏幕」,这坑必然只能等实机验收暴露。

## 修法

`vite.config.ts`:`optimizeDeps.exclude: ['@nimotech/nimoos-service']` + `include: ['axios']`。
排除后 dev 直接按需加载 node_modules 里的真实文件。已实证:重启后 dev server 交付的
`sys.js` 含全部 24 个方法(`toggleUsbAutoMount` / `editServerPort` / `setSSLConfig` /
`getGatewayComponents` / `getDeviceInfo` … 都在),且 `PUT /v1/usb/usb-auto-mount`
经 dev 代理实测返回 `{"success":200,...}`。
守卫:`src/viteOptimizeDepsGuard.test.ts`(已做变异验证:删块 / 换包名 / 改字段名三种情况都能翻红)。

**⚠️ `.sp7` / `.sp8` 两个 worktree 有各自的 `vite.config.ts` 与 `node_modules`,同一个坑还在那儿。**
