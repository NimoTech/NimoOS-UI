## 一、⛔ 因「会断 SSH」而整体挂账的部分(用户 2026-07-31 指示)

> 用户原话:**「验证时由于机器不在我身边,会直接导致机器 ssh 连接不上或者断开 ssh 连接的都先不做都记台账到最后做。」**

### 结论:本期 `PUT /v2/nimoos/network/interfaces` 一次都不发(curl 不发、浏览器不点)

### 依据(读 Go 源码逐行确认,不是猜)

1. **SSH 生命线就是被配置的那张网卡。**
   ```
   SSH_CONNECTION=192.168.1.172 65097 192.168.1.143 22
   ip route get 1.1.1.1 → via 192.168.1.1 dev enp2s0 src 192.168.1.143
   ```
   本机 `ip -br addr` 里唯一 UP 的物理网口就是 `enp2s0`;`enp4s0` / `wlp1s0` 都是 DOWN(NO-CARRIER)。
   → 界面列表第一行 = enp2s0 = 唯一"看着能编辑"的东西 = 改了就断线。

2. **哪怕改一张没插线的网卡也不安全。** `NimoOS/route/v2/network.go:88` 在所有分支之后**无条件**调
   `network.ApplyGatewayConfig()`(`NimoOS-Common/pkg/network/gateway.go:21`),它会:
   - `ensureDnsmasqService()` → 若无 unit,**写 `/etc/systemd/system/dnsmasq.service` + `systemctl enable`**
   - `configureDnsmasq()` → 当前零 lan 口 ⇒ `os.Remove(/etc/dnsmasq.d/nimoos-dhcp.conf)` + **`systemctl restart dnsmasq`**;若某口设 lan ⇒ 在该口起 DHCP
   - `configureNftables()` → 重写 `/etc/nimoos/nat.nft` 并 `nft -f`(`delete table ip nimoos_nat` + 重建 masquerade)
   - `enableIPForwarding()` → 写 `/proc/sys/net/ipv4/ip_forward` + **持久化 `/etc/sysctl.d/99-nimoos-routing.conf`**
   → **任何 PUT 都会重写这台机器的 DHCP / NAT / 转发配置**,与目标网卡是否插线无关。

3. `enp4s0` 看着像安全靶子(DOWN、未接线),**但走的是同一个 `ApplyGatewayConfig`** → 一样不做。

### 因此挂账的项(= 债务 D18,需用户在机器旁排期)

| 未验的路径 | 覆盖手段 |
|---|---|
| 配置弹窗「保存并应用」(以太网 dhcp/static · Thunderbolt · wifi client/ap/concurrent 六种 payload) | `buildUpdatePayload` 26 例单测 + 3 次变异验证 |
| 切模式菜单 → 确认框「确认」(裸切 + 重取 config + 开弹窗) | `NetworkPanel` 集成测试(mock PUT)+ 失败分支 |
| Wi-Fi 列表「断开连接」 | 弹窗测试(mock PUT) |

**性质同 P1 的 D17:破坏性 + 只能在浏览器里点才算验 = 只有机主本人在机器旁时能关账。** 不是懒,是结构性的。

### 可以放心做的(已实测无副作用)

## 三、开工前的 9 条实测校正(**后续期直接引用,别再自己猜**)

详见计划书 §实测校正。摘要:

1. config 端点只填 5 个字段,`mac`/`state`/`speed`/`ports` **永远空** → state/speed/addr 一律取 utilization。
2. config 端点可能返回 **`null`**(Go nil slice)→ 必须 `Array.isArray` 守卫。
3. `wlp1s0` 不在 config 里但**必须出现在界面上** → 印证 spec §1.7「列表源是 utilization」,别改成直接列 config。
4. 🔴 **MessageBus 推送缺 `max_speed`**(见上 §二.3)→ `MaxSpeedMemo`。
5. socket 的 `sys_net` 是 **JSON 字符串**,共享包 `parseUtil` 已处理;但 `Utilization.net` 的类型是 `Record<string,unknown>|null` 而真值是数组 → **在 New-UI 侧收窄,不改共享包宽类型**(主页/小组件都在吃它)。
6. `scanWifi` 失败可能是 **200 + null**(见上 §二.5)。
7. network 域错误体是 **`{"error": …}`**,而共享包 `http.ts` 的拦截器只认 `message` → `err.message` 拿不到后端文本 → 包里出 `networkErrorText(e)`。**D21**。
8. `isVirtual` 前缀判定在本机**不可达**:`data.net` 来自 `GetNet(true)` = 只物理口(`helper.sh GetNetCard 2` = `ls /sys/class/net | grep -v <虚拟口>`),docker0/br-*/veth*/virbr0/zt* 永远进不来 → 「虚拟网络」行与隐藏菜单分支只有单测,不列验收项。**D19**。
9. `hybridCapable` 只对 **config 里已有的** wifi 口算(`setHybridCapable`)→ 本机 wlp1s0 不在 config → **「切换到混合模式」在本机永远不出现**,concurrent 双 tab 同理只有单测。**D19**。

### 一处测试写法的自我修正(值得记)

计划里「同一张网卡连点两次扫描」那条**前提是错的**:扫描在途时扫描按钮是 `disabled`,而
**@vue/test-utils 不会给 disabled 元素派发事件** → 第二次扫描根本没发生,断言必然失败。
真实的竞态是**关掉弹窗换另一张网卡打开**(`watch` 里 `scanGen++`),此时前一次 ~2.3 秒的扫描仍在飞。
已按真实路径重写该用例(`wlp1s0` 慢扫描在飞 → 切到 `wlp2s0` 快扫描 → 再让 `wlp1s0` 落定)。
