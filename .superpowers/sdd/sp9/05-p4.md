## 一、⛔ 破坏面判定(读 Go 源码 + curl 实测,开工前定死)

### 1. `PUT /v1/users/current/password` —— ⛔ 一次都不发,连 curl 都不试

`NimoOS-UserService/route/v1/user.go:397-418`:

- `:397` 先 `osuser.VerifyOSUserPassword(user.Username, oldPwd)` 校验旧密码 —— 读 `/etc/shadow`(`pkg/utils/osuser/osuser.go:276-283`)。
- `:403` `osuser.SetOSUserPassword(user.Username, pwd)` → `/usr/sbin/chpasswd`(`osuser.go:41-48`)**写 `/etc/shadow`**。
- `:409-413` 起一个 goroutine `osuser.EnsureSambaUser` 同步 Samba 密码。
- `:416-417` 把 SQLite 里的密码字段清空。

**这台机器的 SSH 登录用的就是 `/etc/shadow` 这套凭据。** 不知道新密码就改不回去 → **不可撤销**。处置:代码写完整 + 单测覆盖,**curl 不发、验收不点**,债务 **D26**。

### 2. `PUT /v1/users/avatar` —— 🟠 会打死 UserService,但后果收敛

`user.go:250-294`:

- `:261` 只 strip `data:image/png;base64,` 这一种前缀 → **必须传 PNG dataURL**。
- `:268-271`
  ```go
  img, _, err := image.Decode(strings.NewReader(string(decodeData)))
  if err != nil {
      log.Fatal(err)      // ← "log" 是 std 库(import 在 user.go:12)
  }
  ```
  **`log.Fatal` = `os.Exit(1)`** → 整个 UserService 进程退出 → 内存 ECDSA 密钥对重生 → **全集群 JWT 立即失效,所有人需重新登录**。
- `:274-285` `os.Remove(avatarPath)` 然后 `os.Create` + `png.Encode` 写 `/var/lib/nimoos/<id>/avatar.png`。

**后果收敛的依据(实测)**:
```
$ systemctl show nimoos-user-service.service -p Restart -p RestartUSec
Restart=always
RestartUSec=100ms
```
服务 100ms 自动拉起 → 最坏结果 = **重新登录一次**,不是服务长期不可用。

处置:代码写完整 + 单测锁死「必须 PNG」契约,**验收默认不点**(债务 **D27**,标注为「机主愿意时成本很低、可单独关账」)。另开后端票 **D29**(用 `log.Fatal` 处理用户输入)。

### 3. `POST /v1/users/members` —— 🟠 真建 Linux 用户

`user.go:845-870`:`osuser.EnsureOSUser(username, false)`(shell `/bin/false`,无 SSH/终端)→ `SetOSUserPassword` 写 `/etc/shadow` → `ApplySystemDiskACL` setfacl 封系统盘 → 建 DB 行 → `file.MkDir(/var/lib/nimoos/<id>)`。只能靠 `deleteUser` 撤,而那个不可撤销。

### 4. `DELETE /v1/users/:id` —— ⛔ 不可撤销

`user.go:643-674`:守卫 `id=="1" || id==callerID` → 撤全部 `setfacl` → `RemoveAllFolderPermissions` → `DeleteUserById` → `RemoveSystemDiskACL` → `osuser.DeleteOSUser`(userdel)→ **`os.RemoveAll(config.AppInfo.UserDataPath + "/" + id)`**。

### 5. `POST` / `DELETE /v1/users/members/:id/folders` —— 🟠 会改 `/DATA` 的 ACL

- grant(`:766-774`):`AddFolderPermission` 是 **upsert**(`service/user.go:85-96`,同 user+path 只更新 permission)+ `osuser.GrantFolderAccess` 真 `setfacl`。
- revoke(`:806-816`):删表行 + `setfacl -x`;可用 grant 重建,但新行 id 会变。
- ⚠️ **NimoOS core 启动时只读打开 `user.db` 的 `user_folder_permissions` 表做文件区权限判定**(顶层 CLAUDE.md)→ 授错会影响文件可见性。

### 6. `PUT /v1/users/current` —— ⛔ 不发,且界面不做

Vue2 侧唯一入口是 state 2「更改用户名」,而全仓 `goto(2)` / `state = 2` **零命中** = 死代码(见下 §三 C10)。`setUserInfo` 仍按 spec §5.7 进包但**无消费方**。

### 7. `DELETE /v1/users`(`deleteAllUser`)—— 不进包

核按钮,Vue2 `AccountPanel` 里零引用。判据 = 「界面里没有就不进包」。

## 三、开工前的实测校正(**后续期直接引用,别再自己猜**)

### 🔴 1. 4 个只读端点全部是标准信封

`{success,message,data}`。P1 那个「同一前缀下信封层数按端点不同」的坑在 `users` 前缀下**没有复现** —— 但仍**逐方法写死**,不做自动探测(F1)。

### 🔴 2. `GET /v1/users/avatar` 在本机是 404,前端必须自己兜底

`GetUserAvatar`(`user.go:303-327`)三级回退:`user.Avatar`(DB 里是空串)→ `/usr/share/nimoos/www/avatar.svg` → `/var/lib/nimoos/www/avatar.svg`,**后两个文件都不存在** → `ctx.File()` 返回 404。New-UI 用**首字母圆形块**兜底(与 `SettingsShell` 的 `.set-user-avatar` 同款,不引入新图片资源)。后端票 **D30**。

### 🔴 3. `?token=` 查询参数被 JWT 中间件认

`NimoOS-Common/utils/jwt/jwt_helper.go:51-57` 的 `TokenLookupFuncs`:**Authorization 头优先,否则取 `c.QueryParam("token")`**。`<img>` 挂不了请求头,所以 Vue2 的 `v1/users/avatar?token=<jwt>` 是唯一可行写法,照抄。

### 🔴 4. `GetAllMembers` 只隐藏调用者本人,**不隐藏其它管理员**

`user.go:694-697` 的注释明确写了「Only hide the current caller from the management list, but show all others including other admins」。→ 「成员」列表里可能出现 `role==='admin'` 的行,**消费方不要按 role 过滤**。

### 🔴 5. 本机零成员 → 成员行与授权列表结构性不可见

`/users/members` 返回 `[]`。不创建成员就看不到成员行、`folder_count`、授权列表 —— 而创建成员是写操作(用户已拍板不点)。**同 P3-D22「验不了 ≠ 没验」的性质**,债务 **D28**。

### 🔴 6. spec §5.7 的「权限矩阵」与 Vue2 源码不符

spec 写「表头、行、各子系统列的开关」,而 `FolderPermissions.vue`(337 行)实际是**四个纵向堆叠的分区**(文件名索引 / 知识库 / 禁止 AI 访问的文件夹 / 照片),各自一份列表,**没有矩阵表头、没有列**。按 P0 先例(「spec 与源码出入,以源码为准」)**照源码做四分区**。计划 §C3。

### 📝 7. `grantMemberFolder` 是 upsert

`service/user.go:85-96` 用 `Where(...).Assign(...).FirstOrCreate(...)` → 同 user+path 重新授权 = **改权限**,不会重复插行。所以 spec 说的「增删改」里的「改」不需要单独接口。

### 📝 8. 全 31 个语言文件都缺译的 key 共 31 条

脚本核过(`NimoOS-UI/src/assets/lang/*.json`,31 个文件)。按 P2 授权偏离 #8 / P3 #10 先例补中文译 —— **待用户拍板**。另 51 条在 `zh_CN.json` 里有中文,已用脚本逐字节取进计划 §i18n 全表。

### 📝 9. `AccountPanel` 有 6 个 state,不是 brief 列的 4 块

`state` 1=账号 / 2=改名(**死代码**) / 3=改密 / 4=裁剪头像 / 5=成员文件夹授权 / 6=从 NAS 选图。brief 的「头像上传」实际含 state 4 + state 6 两屏。设置区是 `isInline=true` → **头部标题被隐藏、页脚保留**(`v-if="!isInline"` / `v-if="state !== 1"`),所以 New-UI 保持「面板内状态机 + 底部 Back/Submit」形态,不改成一堆弹窗。

## 五点五、过程教训(边做边记)

1. **`attachTo: document.body` 的弹窗测试必须显式清理。** `FolderPickerDialog.test.ts` 第一版三条红,根因是前几次 mount 的 Portal 内容残留在 `document` 里,`querySelector` 取到**上一次**的节点(根按钮数成了 18 = 6 次 mount × 3)。仓内 P3 的 `AppPathDialog.test.ts:49-87` 早有同款教训与写法(跟踪 wrapper + `afterEach` 统一 unmount + 清 `document.body.innerHTML`)—— **B4「attachTo body 并查 document」这条要求得连着清理一起写,只写前半句会栽。**
2. **Go 零值时间的格式化输出是 `1-01-01` 不是 `0001-01-01`。** Vue2 `formatDate` 只对月/日/时/分/秒 `padStart`,年份直接用 `getFullYear()`。且公元 1 年的本地偏移是 LMT(本机 Asia/Shanghai = +08:05:43),所以时分秒也不是 `00:00:00`、**随测试机时区变** → 断言不能写死完整字符串。按 1:1 保留不改(不是 bug/竞态/吞错)。
3. **变异验证逮到一条空转用例 + 一条结构性无法测的冗余。** `nasNavigateUpTarget` 的「不会越过根往上」原用例传 `('/mnt/X/y','/mnt/X')`,而路径在根之下时父目录长度必然 ≥ 根 → **夹紧分支压根没被走到**,改成恒返回 `parent` 也全绿。真实路径是「当前路径不在根之下」(`('/mnt/Other','/mnt/DeepRoot')`),改用它后变异立刻翻红。另外 Vue2 那个 `|| nasRootPath` 兜底在夹紧存在的前提下**任何用例都无法区分**(空串时 `0 >= root.length` 恒 false,同样回落到根)→ 照抄保留但**不留空转用例**,在实现与测试里都写了注释。
4. **计划里 T3 的面板 import 了 T4 才创建的弹窗**,按原顺序 T3 单独编不过 → 实际执行时调换成「先弹窗、后面板」。
5. **9 个 tab 全部实现完毕后,`panels.test.ts` 的两条骨架抽查失去了对象**,已合并成一条「没有任何面板还在渲染 `settingsSkeletonHint`」的收口断言。⚠️ **判据要用文案键、不能用 `.set-skeleton` 类名** —— 后者被 AppsPanel/StoragePanel 复用成了「取数在途」的加载态占位(它们的测试正是先断存在、flush 后不存在),拿类名当判据会永远红。第一版就是这么错的。

4. **⚠️⚠️ `beforeEach(() => mock.mockReset().mockResolvedValue(x))` 这种链式写法有毒(本期最费时的一处)。** 箭头函数把 mock **返回**给了 vitest,而 `beforeEach` 支持返回 teardown 函数 → **每个测试结束后 vitest 会再调一次这个 mock**;若该测试把实现换成了「抛错」,那次调用产生的 rejected promise 没人 await → 报成 `Unknown Error: <msg>`,**而断言其实全是过的**。症状极具误导性:看起来像「组件的 catch 没生效」,我换了三种错误对象形状才定位到是 hook 的返回值。**必须写花括号、不返回。**

5. **reka `AlertDialogAction` 在同一次点击里就发 `update:open(false)`,且可能先于 `@confirm` 跑。** 我在 `@update:open` 里清删除目标 → 随后的 `confirmDelete` 读到 `null`、**什么都不删**(两条用例翻红才逮到,这是个真实缺陷不是测试问题)。修法 = 目标存**非响应式**变量、`update:open` 只管可见性。仓内 `files/components/UploadPanel.vue:116-126` 早有一模一样的注释与教训 —— **写弹窗确认前先去看那一段。**
