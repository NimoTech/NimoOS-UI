# 图片查看器缩放"停手落盘"设计(消除瓦线)

日期:2026-07-21 · 范围:`src/files/viewers/ImageViewer.vue` 单组件

## 问题

大图(实证样本 4096×3072)在查看器中缩放时画面出现贯穿整宽的 1px 细白线("瓦线"),
位置随缩放倍数移动。程序化分析真机截图(逐行梯度扫描)确认:线横贯 99-100% 列宽、
线两侧平均色一致但逐像素相位错开 —— 是渲染接缝,非图片内容。

**根因**:Chrome 把大图光栅化成固定尺寸瓷砖缓存;CSS `transform: scale()` 缩放走合成器
快路径时直接拉伸旧瓷砖,砖边采样越界露出 1px 缝。倍数变化改变拉伸比,缝随之移动。
此前已移除 `will-change: transform`(见组件内注释),但 `transition: transform 0.05s`
使每次滚轮都触发 50ms 合成器动画,连续缩放期间动画首尾相接,始终处于拉伸快路径。

瓦线是合成器固有行为,无 CSS 可"修";唯一杠杆是**何时按最终倍数重画**。

## 方案(已确认:混合式)

两个尺寸状态:

1. **交互中(保持现状)**:滚轮/按钮每步改 `transform: scale()`,合成器拉伸缓存瓷砖,
   流畅优先,容忍缝一闪而过。
2. **停手落盘**:缩放操作停止 150ms 后,把当前倍数烙进图片布局尺寸
   (`width/height = 布局尺寸 × scale`,同时 `max-width/max-height: none`),`scale` 归 1。
   布局尺寸变化强制浏览器按最终大小重画 —— 该路径逐砖从原图采样,结构上无缝,
   且比拉伸旧砖更清晰。

## 关键细节

- **落盘零跳动**:图片 flex 居中,宽高增长围绕中心对称,与 `scale()`(默认中心原点)视觉
  等价;`tx/ty` 写在 transform 列表中 scale 左侧,数值不受 scale 影响,落盘后依然有效。
- **transition 闪动**:落盘帧 scale N→1 会被 `transition: transform 0.05s` 动画化,而宽高
  瞬变,会闪一下 —— 落盘那一帧临时 `transition: none`,双 rAF 后恢复。
- **倍数记账**:`committedZoom`(已落盘总倍数,初始 1)× `scale`(交互增量)= 有效倍数,
  钳制在 [0.1, 8]。落盘时 `committedZoom *= scale; scale = 1`。
- **复位/翻页**:清落盘尺寸回 CSS 自适应(contain),`committedZoom=1`,取消挂起的落盘定时器。
- **旋转**:留在 transform 里,与落盘尺寸正交,不处理。
- **未加载守卫**:`offsetWidth === 0`(图未加载完)时跳过本次落盘,不破坏显示。
- 不改后端、不改其他文件。

## 测试与验收

- 单测(vitest,同目录 `ImageViewer.test.ts`):停手 150ms 后 scale 归 1 且写入 width/height;
  连续缩放期间不落盘;复位/翻页清落盘状态;既有三条用例不回归。
- 真机验收:`./scripts/deploy.sh` 部署后,对 4096×3072 样本图缩放到最大倍数,截图做
  逐行梯度扫描 —— 静止画面无贯穿整宽的 1px 突变线;高倍数下文字边缘较拉伸态更锐。
