## 发现一(重要)—— color-guard 的 `.css` 那一半一直是空转的

**这是既有缺陷,不是本期引入的。** 两处叠加:

1. **vitest 默认 `css: false`**,所以 `?raw` / `?inline` 读 `.css` **恒返回空串**。glob 的 key 都在、
   值全是 `''` → 任何 `.css` 都"通过"。
2. `import.meta.glob('../**/*.css')` 给出的 key 是 `'./theme.css'` 而**不是** `'../styles/theme.css'`
   (`.vue` 的 key 才带 `../`)。于是跳过条件 `rel === 'styles/theme.css'` **从未命中** ——
   连 `theme.css` 自己都在"被扫",只是内容为空所以不报。

结果:`src/files/viewers/viewers.css` 从未被真扫过(万幸它干净,两处都是合法的 `var(--fg, #fff)` fallback)。

**修法**:`.css` 改用 `node:fs` 递归读(`.vue` 的 `?raw` 正常,保持 glob),并把 `theme.sp9.css`
一并加进跳过名单。测试数 131 → 129:两个 token 定义文件不再生成内容为空的假测试,`viewers.css`
第一次真被扫。

**代价**:装了 `@types/node`(devDependency,仅类型)。用**文件级 `/// <reference types="node" />`**
而不是往 `tsconfig.json` 的 `types` 数组加 `"node"` —— 后者会把 NodeJS 的 `setTimeout`/`Timer`
声明灌进整个 `src`,改变既有代码的类型推断。这是对 spec §4.4「依赖只装一次」的一处偏离,理由如上;
在 `.sp9` 独立工作树下,该约束原本要防的「搅动共享 node_modules」已不成立。

> **今后凡是要在测试里读 `.css` 源码,一律用 `node:fs`,别用 `?raw` / `?inline`。**
