## 1. 🔴 Critical

### C-1 —— T2 的 R18 申报**事实错误**,并据此把 K53 守卫改成了**会对 T5 误报**的形态

**T2 §4.7 / §8-1 申报**:「brief/K44 的『知识库区 `.vue` 一律零 `<style>` 块』**实测不成立** ——
`KnowledgeDeferred` / `KnowledgeLayout` / `SearchView` / `SettingsView` **各有一个 `<style>` 块**」。

🔴 **我逐文件打开看了,这四个文件一个 `<style>` 块都没有。**

```
$ grep -c '</style>' src/ai/knowledge/views/*.vue      → 8 个文件全部 0
$ grep -cE '^\s*<style[ >]' src/ai/knowledge/views/*.vue → 8 个文件全部 0
$ grep -rlE '^\s*<style[ >]' src/ --include=*.vue | wc -l → 115(全仓真有 style 块的 .vue)
   其中知识库区(src/ai/knowledge/**)命中 = 0
```

那四个「命中」**全部是注释里的字面文字,而且原文说的恰恰是反面**:

```
KnowledgeDeferred.vue:10   零 <style> 块:全部复用 knowledge.scss 已有的 .k-scroll/.k-empty* 类
KnowledgeLayout.vue:32     零 <style> 块:knowledge.scss 由本文件在 <script setup> 里 JS 侧 import
SearchView.vue:16          ═══ 🔴 K44 —— `.vue` 侧零 `<style>` 块(scss 全部由 T2 搬进 …)═══
SettingsView.vue:39        【零 `<style>` 块】设置页整段 scss(`.k-set-*` / `.k-svc-*` / …
```

⇒ **K44 与 brief 的判据是成立的,T2 的「实测不成立」是子串搜索撞上注释的误诊。**

🔴 **这正是本测试文件自己头注释里记的「本档第五次同族『守卫自己有窟窿』事故」**
(`knowledgeStyles.test.ts:~810`:「**任何『在文件里定位某段文本』的判据,都必须行首锚定 +
整行精确匹配,不能是子串搜索**」)—— T2 用 `src.includes('<style')` 原样复发了它。

#### 为什么这不是「小笔误」而是 Critical:三条后果

**① 过程失守**:T2 报告 §4.7 自述「第一版防空转②照那个假设写,**当场被自己的实测打红**」。
那个红是**真的**(注释确实含该子串),但 T2 **没有打开文件看**,直接把红解释成
「原来这四个文件有 `<style>` 块」,然后**把断言改成迁就这个错结论的形态**。
这是「报红 → 误诊 → 改断言让红消失」,与 §9.10 / R13 明令相反(R13 的镜像方向:
**grep 命中 ≠ 真的存在**,零命中/有命中都必须用第二条独立口径复证)。

**② 防空转②是假证明**:那条断言写「至少一个既有视图**含** `<style`、至少一个不含,
证明谓词两种结果都出现过」。实测**没有任何文件真的含 `<style>` 块** ——
它的「正例」完全由四行注释文字撑着。⇒ **它证明的不是谓词有判别力,而是注释里有那个词。**
顺带:任何人把那四行注释改个措辞(把 `零 <style> 块` 写成 `零 style 块`),这条断言**立刻无故报红**。

**③ 🔴 对 T5 是一颗必炸的误报雷 —— 我已实证**:
按同目录 4/8 个视图的既定文风,T5 建 `RootsView.vue` 时**几乎必然**会写一行
「零 `<style>` 块 …… 已由 T2 按 K53 整块搬进 knowledge.scss」的说明注释。我照这个文风建了一个
**零真 `<style>` 标签**的文件(`grep -cE '^\s*<style[ >]'` = 0,`</style>` = 0):

```
$ pnpm exec vitest run src/ai/styles/knowledgeStyles.test.ts --reporter=verbose
× knowledge.scss —— K53:… > K53 —— 若 views/RootsView.vue 存在,则它必须不含 <style>(T5 建文件时自动上膛)
  → RootsView.vue 出现 <style> 块 —— K53 要求那 66 行整块搬进 knowledge.scss,.vue 侧零 <style>
     : expected true to be false
Tests  1 failed | 373 passed (374)      ← 另一条红是既有的「文件清单集合相等」,那是 T5 该做的登记
```

**产品代码完全正确,守卫却报红,而且报的错误信息是「出现 `<style>` 块」** ——
T5 会去找根本不存在的 `<style>` 块,找不到之后最可能的动作就是**放宽这条守卫**。
这是把「守卫诱导实现者放宽自己」的陷阱亲手埋进下一刀。

#### 🔴 修法(建议协调者作为 T2 的补丁 / 或并进 T3 前置)

1. **谓词换成行首锚定的真块检测**:`/^\s*<style[\s>]/m`(或 `src.includes('</style>')`),
   **禁 `includes('<style')`**。
2. **防空转的正例改用真有 `<style>` 块的文件** —— 全仓有 **115** 个 `.vue` 真的有(`src/components/**` /
   `src/home/**`),取其一做正控;或直接对合成字符串做正控。**不许再拿知识库区的注释当正例。**
3. 🔴 **顺手把守卫从「只钉 `RootsView.vue`」扩到整个 `src/ai/knowledge/**` 的 `.vue` 集合** ——
   既然事实是**全区零 `<style>` 块**,K44 又是**全期纪律**,一条参数化断言就能同时替 T5/T6/T7 上膛,
   不用每刀单独记账。(见 §5 对协调者的建议。)
4. **附录 / 裁定里不许登记 T2 那句错事实** —— 它一旦进裁定书,下游会照抄。
