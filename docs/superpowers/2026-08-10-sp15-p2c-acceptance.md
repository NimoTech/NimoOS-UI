> 分支 `sp15-photos-moments`，代码末位见文末「六道门」一节。**未部署、未推 origin、未合 master。**
> 靶子是 Vue2 `33b05636`（`NimoOS-UI` 仓）。本期改动集中在两个页面：
> `/photos/albums/:id`（相册详情，整页在智能视图详情的骨架上重建）与
> `/photos/smart-views/:id`（智能视图详情，动作行搬进侧栏、菜单统一成五项），

## 第 0 步（必读 · 预期基线，跳过会把正常当缺陷、或把缺陷当正常）

**本机数据**（后端真实状态，不是假设）：

| 表 | 行数 |
|---|---|
| `albums` | 5 |
| `album_assets` | 40 |
| `smart_views` | 9（**全部 paused，从未评估过**） |
| `moments` | 0 |

### 允许为空 / 显示占位符的地方（**这些不是缺陷**）

1. **相册详情侧栏「关于」段的「地点」行**：相册成员照片若不带 GPS，这一行显示占位破折号
   `—`，鼠标悬停也没有提示。这是**预期**。本机相册照片多数无 GPS，五个相册里可能一个
   地点都读不出来。
2. **相册详情侧栏的「按月分布」直方图**：这一节只在成员照片**带拍摄时间（EXIF takenAt）**时出现。
   全无拍摄时间的相册看不到直方图，是预期。
   ⚠️ 但**至少要在其中一个相册上看到直方图** —— 40 行 `album_assets` 不可能一张都没有时间。
   如果五个相册全都没有直方图，那要当缺陷记下来。
3. **智能视图详情页的照片网格**：9 个智能视图全是语义条件且从未评估过（撞后端 BE-1，
   `text.token_embedding.weight` 缺 1.1 GB），所以**自动匹配数恒为 0**，网格空是预期，
   不是本期缺陷。
   👉 **要验智能视图页的排序/密度/灯箱，必须先手动塞照片进去** —— 做法见**第 10 步开头**
   那一段引用块（「先塞照片」）。**这是本清单最容易被跳过的前置条件**：不塞照片就去验
   第 10 步和第 12 步，页面明明是好的，也会看起来「什么都没发生」。

### ⛔ 不允许为空的地方（**看到就是缺陷，别放过**）

上一期（P2b）的验收清单在这一点上错得很危险：它预先声明「看到近乎空白是预期」，机主
照单验收就会签字通过一个真正坏掉的页面。所以这一期把界线写死：

打开任意一个相册详情页（第 1 步给了点击路径），**下面这些必须全部看得见**，
少任何一项都是缺陷，**不能用「数据为空」解释掉**：

- [ ] 整页不是白屏/不是只有一个左侧全局导航栏
- [ ] 顶部返回条（「相册」返回按钮）
- [ ] 页头：相册名（大标题）+ 下面一行「N 项 / N 视频」统计
- [ ] 页头右侧动作行：「排序：<当前排序>」下拉 + 分隔线 + 「编辑」按钮 + 分隔线 + 密度两连按钮
- [ ] 右侧栏 **三节都在**：
  - 顶部的「⋯」按钮（侧栏第一行）
  - **「关于」**段（四行：类型 / 创建于 / 时间跨度 / 地点，值可以是 `—`，但**行必须在**）
  - **「统计」**段（两个数字格子：照片 / 视频）
  - **「按月分布」**段（柱状图，**允许缺席**，见上面第 2 条）
- [ ] 点「⋯」能弹出菜单，且菜单里**恰好五项**

## 验收步骤

### 1. 进入相册详情页（后面所有相册相关步骤的共同起点）

点击路径：左侧全局导航 → **相册** → 打开 `/app/#/photos/albums` → 在网格里
**点任意一张「手动相册」卡片**（没有右上角「智能视图」小徽章的那种）→ 进入
`/app/#/photos/albums/<id>`。

- [ ] 地址栏变成 `#/photos/albums/<数字>`
- [ ] 第 0 步「⛔ 不允许为空」那张清单逐条对照，全部满足

> 记下这个相册的名字（下面称**相册 A**）：后面第 **2/3/4/5/6/7/8 步**、以及
> **第 12 步的最后一项**，都从这个页面开始。
>
> ⚠️ **第 9 步（转成智能相册）刻意不用相册 A**，那一步会另挑一张手动相册（相册 B）——
> 转换会把源相册变成智能视图，相册 A 一旦被转走，第 12 步最后一项就没有相册可验了。

### 2. 页头排序下拉：宽度 + 勾选图标

点击路径：第 1 步的页面 → 页头右侧「**排序：手动排序**」那颗药丸按钮 → 弹出下拉。

- [ ] 下拉面板**明显比按钮宽**（目标是最小 240px；本期从 180px 改上来的，
      改动前它窄到贴着文字，改动后三个选项左右都有余量）
- [ ] 三个选项：**手动排序 / 拍摄日期 / 添加日期**
- [ ] **当前选中那一项左边有一个「✓」对勾图标**，另外两项左边是**等宽的空位**
      —— 三个选项的**文字左边缘必须对齐成一条竖线**（这是本期修的 1:1 破绽，
      改动前当前项只有一层背景色、没有对勾，三行文字齐平但没有勾）
- [ ] 选中项还带一层浅色高亮背景
- [ ] 点「拍摄日期」→ 下拉关闭，按钮文字变成「排序：拍摄日期」，网格顺序变了
- [ ] 再点开下拉 → 这次对勾跑到「拍摄日期」那一行

### 3. 密度切换

点击路径：第 1 步的页面 → 页头右侧最右边那两颗小图标按钮（大格/小格）。

- [ ] 点右边那颗（紧凑）→ 照片格子明显变小、一行放得下更多张
- [ ] 点左边那颗（舒适）→ 变回大格
- [ ] 当前生效的那一颗有高亮底色

### 4. 编辑态 + 底部浮条

点击路径：第 1 步的页面 → 页头右侧「**编辑**」按钮。

- [ ] 按钮文字变成「**完成**」
- [ ] **排序下拉和密度两连按钮整组消失**（编辑态下只剩「完成」这一颗），
      而且**左右两条竖分隔线也跟着消失**，不能留下孤零零的竖线
- [ ] 屏幕**底部中间**浮出一条横条（不是贴在页面底、是浮在照片上方、居中）
- [ ] 浮条左边是提示文字「**点击选择 · 拖动排序**」
      （**不含**「★ 设为封面」那一截 —— 浮条上没有设封面这个动作，那句话只出现在
      鼠标悬停单张照片时的 tooltip 里；本轮修的就是这处 1:1 破绽）
- [ ] 浮条右边两颗按钮：「**从相册移除**」（此刻**灰掉不可点**）+「**添加照片**」
- [ ] 点一张照片 → 它出现选中角标，浮条左边文字变成「已选择 N 项」，
      「从相册移除」**变成可点**
- [ ] 再点一次同一张 → 取消选中，「从相册移除」重新灰掉
- [ ] 点「完成」→ 浮条消失，排序下拉和密度按钮回来

> ⚠️ 这一步**不要**真的点「从相册移除」（会改数据）。要点也行，记得点完把照片
> 用「添加照片」加回去。

### 5. 侧栏「⋯」菜单：五项

点击路径：第 1 步的页面 → **右侧栏最上面那颗「⋯」按钮**（不在页头，在侧栏顶部）。

- [ ] 菜单弹出，**从上到下恰好五项**，每项都是「图标 + 标题 + 灰色小字说明」两行：
  1. **重命名** — 修改相册名称
  2. **复制** — 把照片复制为一个新相册
  3. **下载为 ZIP** — 「N 张照片 · 约 N MB」
  4. **转换** — **转为持续自动更新的智能相册**
     （注意：这句**不是**第 9 步弹窗里的副标题「Nimo 会自动持续加入匹配的新照片」——
     靶子里这是两句不同的文案，本轮把它们分开了）
  5. **删除** — 照片会保留在图库中（**红色**，上面有一条分隔线）
- [ ] 第 5 项「删除」的文字和图标是**红色**，前四项是正常前景色
- [ ] 鼠标划过任意一项都有底色变化；划过「删除」时**底色是淡红、文字仍然清晰可读**
      （不能变成白底白字或红底红字）
- [ ] 按 `Esc` → 菜单关闭
- [ ] 点菜单外面任意空白 → 菜单关闭

### 6. 短视口下「⋯」菜单向上翻转 ⭐

**这一步的顺序不能反** —— 菜单在窗口 resize 时会自动关闭，所以必须**先把窗口调矮，
再点「⋯」**。

点击路径：
1. 在第 1 步的页面上，把浏览器窗口**高度拖到很矮**（约 500px 以内；
   或按 F12 打开 DevTools 并停靠在**底部**，把 DevTools 拉高，把网页可视区压矮）
2. **滚动侧栏，让「⋯」按钮落在屏幕靠下的位置**
3. 这时**再**点「⋯」

- [ ] 菜单**向上展开**（菜单底边贴在「⋯」按钮上方），而不是向下被屏幕底边切掉
- [ ] 菜单**五项全部可见**，没有被截断、没有出现内部滚动条
- [ ] 菜单**没有被侧栏边界裁掉**（它是 fixed 定位，会浮在侧栏之外）
- [ ] 现在**滚动一下侧栏** → 菜单**自动关闭**（这是刻意的行为，不是 bug）
- [ ] 把窗口高度恢复正常，再点「⋯」→ 菜单**向下**展开

### 7. Download as ZIP —— 必须真的点一次 ⭐⭐

**这一项自动化测试验不出来**（jsdom 里没有真实的文件下载），所以只有真机点击能证明。

点击路径：第 1 步的页面 → 侧栏「⋯」→ 第 3 项「**下载为 ZIP**」。

- [ ] 菜单立刻关闭
- [ ] 屏幕上弹出 toast「**正在打包 ZIP —— N 张照片**」
- [ ] **浏览器真的开始下载一个 `.zip` 文件** —— 看浏览器下载栏 / 下载目录：
      文件确实落盘、**大小不是 0 字节**
- [ ] 下载没有把当前页面顶掉（页面还停在相册详情，没有跳走、没有变白）
- [ ] 用解压工具打开这个 zip，里面**确实有照片**，张数与相册的「N 项」大致对得上
- [ ] ⚠️ 如果浏览器提示「未经授权」/ 下载 0 字节 / 下载下来是一个 JSON 错误文件，
      **记为缺陷**（这条路径靠 URL 里的 token 免 JWT，token 拼错就是这个症状）

### 8. 复制（Duplicate）

点击路径：第 1 步的页面 → 侧栏「⋯」→ 第 2 项「**复制**」。

- [ ] 弹出 toast「已复制「<相册名>」——可在列表中打开新副本」
- [ ] 返回 `/app/#/photos/albums`（点页面左上角「相册」返回按钮）
- [ ] 网格里**多了一张卡**，标题是原相册名的副本，封面和照片数与原相册一致
- [ ] ⚠️ 验完请把这个副本删掉（进副本详情 → 侧栏「⋯」→「删除」→ 确认），
      免得污染后续验收的相册计数

### 9. 转换：手动相册 → 智能相册

⚠️ **这一步会把源相册消耗掉**（转换后它变成智能视图，不再是相册），所以**不要用相册 A**。

点击路径：`/app/#/photos/albums` → 另点一张**手动相册**卡片（**不是**第 1 步那张，
下面称**相册 B**）→ 进入它的详情页 → 侧栏「⋯」→ 第 4 项「**转换**」。

- [ ] 弹出一个模态框，标题「转为智能相册」，副标题「Nimo 会自动持续加入匹配的新照片」
- [ ] 模态里 Nimo 给出**若干条建议条件**（chip 形态），并有一句
      「现有 N 张照片将保持锁定，Nimo 会按这个主题持续加入新照片」
- [ ] **建议条件请选日期类的**（例如含年份/月份的那种）；
      语义类（人物/场景）撞后端 BE-1，转换后匹配数恒为 0，验不出效果
- [ ] 点确认 → 按钮变成「转换中…」→ 成功后 toast「已转为智能相册」
- [ ] **页面自动跳到 `/app/#/photos/smart-views/<新 id>`**（地址栏能看出来）
- [ ] ⚠️ 如果 `设置 → AI 行为` 里智能视图开关是**关的**，这一项应该是**灰掉不可点**，
      鼠标悬停显示「智能视图已关闭——请在「设置 · AI 行为」中重新开启后再创建。」
      —— 这也是一个要验的分支：去设置里关掉开关，回来看这一项确实灰掉，再开回去。

- [ ] 密度两连按钮：紧凑/舒适切换有效，当前项高亮

### 11. 智能视图详情页的「⋯」菜单：与相册页同形

### 12. 灯箱按网格当前顺序打开 ⭐

> 顺序说明：这一步**排在反向转换（第 13 步）之前**是刻意的 —— 第 13 步会把第 10 步那个
> 智能视图冻结成普通相册，它一转走，这一步就没有「塞过照片的智能视图」可验了。

点击路径：第 10 步的页面（已塞过照片）→ 先把排序切到「**拍摄日期**」→
**点网格里的第 3 张照片**打开灯箱。

- [ ] 灯箱打开的**就是你点的那一张**
- [ ] 按 `→` 右方向键 → 出现的是网格里**紧挨着它右边的那一张**（不是别的）
- [ ] 一路按 `→` 到底 → 走过的顺序与网格里从左到右、从上到下的顺序**完全一致**
- [ ] 关掉灯箱，把排序切回「**匹配分数**」，再点第 3 张打开灯箱、再按 `→`：
      顺序应当**跟着新的网格顺序变**，而不是停留在旧顺序
      （本期修的就是这个：改动前灯箱走的是 store 里的原始数组顺序，和眼前网格对不上）
- [ ] **相册详情页做同样的事**（回到**相册 A**，即第 1 步那个页面 → 排序切「拍摄日期」→
      点第 3 张 → 按 `→`）：同样跟随网格顺序
      （相册 A 此刻仍在 —— 第 9 步用的是相册 B）
