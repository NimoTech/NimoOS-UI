## 1. `?section=blacklist`(文件系统)—— agent 组竖排 stack 的第一屏

1. 打开 `?section=blacklist`,**不要等** —— 观察整页:agent 组的 5 个分区(文件系统 / 执行
   步数 / 搜索 / 记忆 / Agent 监控)应该**竖排叠在同一页**,一次性全部挂载并各自发起自己的
   首屏请求(并发首次加载)。预期:5 个分区各自的骨架/空态短暂闪一下,然后各自数据陆续
   回填,**互不阻塞**(某个分区接口慢或报错不应卡住其它分区的渲染)。**这一条(agent 组
   5 分区并发首挂)没有专门的自动化测试**——各分区的 `.test.ts` 都是单独 mount 单个分区,
   没有测过"5 个同时挂载"的场景。
2. 「内置(只读)」列表应该渲染出一串 pattern(`**/.ssh/**` 等 26 条),每条前面一个锁图标,
   都不可编辑、没有删除按钮。
3. 「你的 pattern」区:在输入框填 `*.bak`,点「+ 添加」→ 出现在列表里,输入框清空。
4. 刷新页面重新进来,刚加的 pattern 应该还在(后端持久化)。
5. 点某一条自定义 pattern 右边的垃圾桶图标 → 该条从列表消失。
6. 填一个会被后端拒绝的非法 pattern(比如极长字符串或非法 glob,视后端校验规则)→ 点
   「+ 添加」→ 应该弹一条红色(danger)toast,输入框内容不清空,列表不变。

## 2. `?section=execution`(执行步数)

1. 「无限(不限制步数)」开关**拨开** → 立即触发保存,`disabled` 的数字输入框应该变灰;
   短暂显示「已保存」文字,**约 2 秒后自动消失**(不是永久挂着)。
2. 把开关拨回**关**,数字输入框改成一个新数字(如 `25`)→ 失焦(`change` 事件)→ 触发保存,
   同样短暂显示「已保存」并自动消失。
3. 把数字框填 `0` 或负数 → 失焦触发保存 → 数字应自动归一成 `1`(不是留着 0 或负数)。
4. (需要能让后端保存接口报错才能测,如断网重试)保存失败时应弹红色 toast,「保存中…」不应
   卡住不消失。

## 3. `?section=search`(搜索)

1. 「默认搜索源」三个 chip(语义/文件名/图片)全部取消勾选 → 应出现「至少选择一个搜索源。」
   提示,「保存」按钮变 disabled。
2. 勾回至少一个 → 提示消失,「保存」按钮恢复可点。
3. 改任意数字框(语义/文件名/图片返回数、合计上限)→ 点「保存」→ 短暂「已保存」文字后自动
   消失。
4. 文件名索引区:点「立即重扫」→ 按钮短暂 disabled,**约 1.5 秒后**诊断区的「索引状态」/
   「已索引文件数」应该刷新(即使数字没变,也应该重新发一次请求 —— 可用浏览器 Network 面板
   确认)。
5. **重点(这是本期修的一个静默失败,务必验证)**:诊断区若显示"⚠ 文件监视已降级为仅定时
   扫描"或 inotify 上限低于推荐值,会出现一个「复制」按钮(复制调大上限的命令)。**在纯
   `http://`(非 `https://`、非 `localhost`)访问下点这个「复制」按钮**——应该弹「已复制」
   toast 且系统剪贴板里真的有内容(粘贴到地址栏验证)。Vue2 原版在明文 HTTP 下点它是**毫无
   反应**(`navigator.clipboard` 在非安全上下文是 `undefined`),这是本期修掉的缺陷,必须在
   真机明文 HTTP 环境验证,不能只信任 `localhost`(`localhost` 被浏览器视为安全上下文,不会
   暴露这个问题)。
6. 加一个根目录(点「添加根目录」,填个路径)→ 点「保存」→ 应立即生效(接口层面无需重启),
   横幅提示文字应说明这一点。
7. 切换「启用文件名索引」开关或改扫描周期 → 保存后应出现「根目录 / 索引设置已更改,需重启
   搜索服务后生效。」的黄色横幅。

## 4. `?section=memory`(记忆)

1. 关闭「启用记忆」开关 → 应出现警告横幅「记忆已关闭 —— 不再记录或注入新内容。已有条目
   保留,仍可删除。」,已有记忆列表不消失。
2. 把「上下文窗口」输入框清空(删掉数字)→ 失焦触发保存 → 刷新页面重新进来,应该**仍是
   空的**(说明发给后端的是 `null` 而不是把旧值当默认值发回去)。
3. 每条记忆右侧标签(偏好/事实/目标 + 来源标签)应该都是**中文标签**,不是原始英文枚举值
   (如 `preference`/`tool`)——除非故意让后端返回一个未知枚举值,这种情况下才应该看到原样
   的英文/未知字符串直接显示(这是有意的兜底行为,不是 bug)。
4. 点某条记忆的删除(垂直的 X 图标)→ 该条从列表消失;若删除失败(需要模拟后端报错),应弹
   红色 toast 且**该条记忆条目仍留在列表里**(不是先移除再恢复的闪烁)。

## 5. `?section=observability`(Agent 监控)—— Phoenix 安装/停止全流程

**此分区没有本地 mock 可以完全模拟,必须在真机上跑一次完整的安装/停止流程。**

1. 若 Phoenix 从未安装:拨开「启用 Agent 监控」开关 → 应弹出确认对话框「Agent 监控需要
   Phoenix 应用(Docker)。现在下载并安装?」。
   - 点「取消」→ 开关应该弹回**关**(不是停留在开的视觉状态)。
   - 点「下载并安装」→ 应显示安装进度(百分比,来自 MessageBus 的
     `app:install-progress` 事件),安装完成后 Phoenix 状态应变为「运行中」,「打开 Phoenix」
     按钮出现,点击应在新标签页打开 `http://<host>:6006/`。
2. 已安装且运行中时,关闭「启用 Agent 监控」开关 → 应弹确认框「关闭将同时停止 Phoenix
   容器以节省资源,是否继续?」。
   - 点「取消」→ 开关应弹回**开**(注意:这里"取消要复位"的方向和 Vue2 不完全一样,是本期
     申报过的一处逻辑修正,详见 `ObservabilitySection.vue` 头注释「框架 API 差异」——验收只
     看结果:取消后开关必须回到开,不能停在关)。
   - 点「继续」→ Phoenix 容器应真的停止(可用 `docker ps` 在设备上确认),开关最终落在关。
3. **验证卸载守卫**:在安装进度条走到一半时,快速切到别的分区(比如点导航切到「模型」组)
   把本分区卸载,然后等足够久(> 40×2000ms ≈ 80 秒保险起见等 2 分钟)——不应该看到任何
   与本分区相关的报错或状态串改(可通过控制台观察,或者切回本分区看状态是否合理,不应该有
   "半途状态"卡死的情况)。**这条没有对应的浏览器级自动化测试**,只有组件级单测模拟了
   `alive` 标记,真实的路由切换 + 定时器场景需要人工走一遍。
4. 应用区(如果本期已有"已安装应用"列表页)**不应该**出现 Phoenix 的安装进度磁贴 —— 这是
   D4 申报的有意架构分歧(本分区自己订阅 MessageBus,不复用应用区的 store)。

## 6. `?section=mcptokens`(对外 MCP 服务)—— 含弹窗视觉验收

1. 「MCP 端点」区应该显示形如 `http://<当前访问地址>/v1/ai/mcp-rpc/` 的只读 URL,点旁边
   「复制」→ 弹「已复制」,粘贴验证真的复制到了这段 URL(**同第 3 节第 5 条,务必在纯 HTTP
   环境验证,不要只在 localhost 测**)。
2. 「接入 AI Agent」区两个只读文本框(接入说明 + JSON 配置),里面应该看到占位符
   `<YOUR_TOKEN>` 出现在指令文本和 JSON 里,**不应该看到裸露的 `{url}`、`{token}` 字面量**
   (如果看到说明 i18n 转义坏了,是阻断级缺陷)。两个「复制」按钮各自复制对应内容。
3. 点「创建令牌」→ 弹出一个输入框弹窗,填个标签(如"验收测试"),确认。
4. **明文令牌弹窗(D1 唯一未自动化验证的视觉点,重点验收)**:
   - 弹窗应该**相对浏览器视口居中**(不是相对页面顶部或某个滚动容器偏移的位置)。
   - 弹窗底色应该是 AI 区的卡片色调(浅色主题下是浅色卡片、暗色主题下是深色卡片),**不应该
     是透明/默认白底**——如果背景变透明或变白底黑字,说明 reka `DialogPortal` 把内容传送到
     了 `document.body`(脱离了 `.set-app` 的 token 作用域),是阻断级缺陷,立即截图上报。
   - 切换主题(浅色 ⇄ 暗色)后弹窗仍开着 → 配色应该跟着变,不需要关闭重开。
   - 弹窗内令牌明文只显示一次,复制按钮可用;关闭弹窗(右上 ×、点遮罩、Esc 三种方式都要
     各试一次)后重新打开「创建令牌」流程,**不应该在任何地方再看到刚才那条明文**。
   - 列表应在弹窗关闭后刷新,新令牌出现在列表里(显示标签、创建时间、「从未使用」)。
5. 删除一个令牌(点右侧「删除」→ 确认框「确定要删除此令牌吗?」→ 确认)→ 该条从列表消失。

## 7. `?section=channels`(聊天渠道)—— 管理员/非管理员两套视角 + 第二个弹窗

**用两个账号分别验收:一个管理员账号、一个非管理员账号。**

### 非管理员视角

1. 打开 `?section=channels` → **不应该看到「机器人配置」这一整块**(admin-only)。
2. 若管理员已配置了至少一个机器人,「配对聊天账号」区应该列出可配对的机器人,每条右边有
   「生成配对码」按钮。
3. 点「生成配对码」→ **第二个需要视觉重点验收的弹窗**:
   - 同第 6 节第 4 条的三项视觉检查(视口居中 / AI 区卡片底色 / 暗色主题跟随)在这里**再验
     一次**——两个弹窗共享同一个 `SkModal` 外壳,但分别独立挂载,不能只验一次就假设另一个
     也对。
   - 弹窗内应显示配对码(8 位数字/字符)+ 提示文字「此配对码 10 分钟内有效,且仅可使用
     一次。」+ 一段形如「打开 Telegram,给 @<机器人用户名> 发送:/pair <配对码>」的指引
     文字——**重点检查 `@` 和配对码都正常显示,不应该是裸的 `{bot}`/`{code}` 字面量**(同
     第 6 节第 2 条的转义检查)。
   - 点复制按钮 → 复制的是配对码本身(不是整段指引文字),弹「已复制」。
4. 关闭弹窗(三种方式都试)后,若已经用 Telegram 真的完成了配对(需要真实 Telegram 账号 +
   已注册的 bot),「我已绑定的账号」区应该刷新出现新绑定,可以设置默认模型和下载目录。

### 管理员视角

5. 「机器人配置」区可见,点「添加机器人」→ **第三个弹窗**(表单,不含敏感明文,视觉规则
   相对没那么关键,但仍建议顺手看一眼底色是否正常)。
   - 选平台(Telegram / Discord)、填名称、填 token → 若 token 非法或后端拒绝,应保持弹窗
     开着并弹红色 toast「添加失败,请检查 Token。」(**弹窗不应该自动关闭**)。
   - 成功添加后弹窗关闭,表单字段清空,新机器人出现在列表,带 token 尾号(如
     `token ···ab12`)。
6. 每个机器人行的启用开关是**原生 checkbox**(不是本仓其它地方常见的 pill 开关样式)——
   这是刻意 1:1 保留 Vue2 原样,**不是遗漏统一成 `SetSwitch` 的 bug**,验收时不要因为样式
   "不一致"而报缺陷。
7. 删除一个机器人(垃圾桶图标 → 确认框「删除该机器人?其所有配对将失效。」→ 确认)→ 从
   列表消失。
8. 解绑某个用户的绑定(「解绑」→ 确认框「确定解绑该账号?解绑后它将无法再与智能体对话。」→
   确认)→ 从「我已绑定的账号」列表消失。

## 8. Scroll-spy(agent 组 / model 组竖排页通用)

1. 在 `?section=models`(model 组,4 个分区竖排)或 `?section=blacklist`(agent 组,5 个
   分区竖排)页面,**手动滚动**内容区。
2. 左侧导航高亮的分区应该跟随视口里"当前最上面可见的那个分区"实时切换(IntersectionObserver
   驱动的 scroll-spy),**但 URL 里的 `?section=` 不应该跟着滚动改变**(只有点导航才会改
   URL——自动化测试已覆盖"IntersectionObserver 回调高亮视口最上分区但不改 URL query"这条
   核心逻辑,但真实鼠标滚轮/触摸滚动的手感、多个分区同时部分可见时的边界判定,建议人工过
   一遍确认没有肉眼可见的抖动或错位)。

## 9. 明确没有自动化测试覆盖、必须人工验收的点(汇总)

- agent 组 5 个分区并发首次挂载(第 1 节步骤 1)。
- Phoenix 安装/停止的真实 Docker 端到端流程,以及安装中途卸载组件的长时间(>1 分钟)存活
  验证(第 5 节步骤 1-3)。
- 两个明文/敏感弹窗(MCP 令牌明文、Channels 配对码)在**真实浏览器视口**下的居中效果、
  AI 区卡片底色、暗色主题跟随(第 6/7 节——组件测试只验证了 DOM 结构和文案,`jsdom` 测试
  环境不能验证真实布局居中与 CSS 计算色值)。
- 纯 HTTP(非 localhost、非 https)环境下的三处剪贴板复制路径(第 3/6/7 节的「复制」按钮)——
  单测环境里 `copyText` 被 mock 掉了,不会暴露 `navigator.clipboard` 在非安全上下文缺失的
  真实浏览器行为。
- 管理员 / 非管理员两种角色下 Channels 分区的可见性差异(第 7 节)——组件测试用
  `localStorage` 伪造角色,真实场景需要两个真实账号登录验证。
- Discord 机器人邀请链接跳转、Telegram/Discord 真实配对流程的端到端联调(需要真实第三方
  账号与网络出口,本期组件测试全部 mock 掉了后端调用)。
