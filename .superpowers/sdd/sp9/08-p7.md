2. **`agentTool` 与 spec §7.2 写的 `agentSearch` 命名不一致** —— 计划 Task 0 改的名,所有

### D-A(**先于本期存在的真缺陷,单开票**)—— 预览开着时按一次 Esc,预览与搜索面板一起关
- **现象**:搜 `receipt` → 点结果行开预览 → 按一次 Esc → 预览关了,**搜索面板也一起关了,
  退回桌面、结果全丢**,用户要重开面板重搜一次。
- **根因(已取证,不是猜)**:`SearchDialog.vue:241` 的守卫 `if (viewer.open.value) e.preventDefault()`
  依赖「读到 `viewer.open.value` 还是 true」;但 `ViewerHost.vue:29` 在 Home 挂载时就把 keydown
  挂到了 `window`,**比 reka 弹窗的 Esc 监听注册得早** → 同一个 Esc 里 ViewerHost 先 `v.close()`
  把标志同步置 false,轮到 `onEscapeKeyDown` 读时已是 false → 不 `preventDefault()` → 弹窗
  照常关闭。CDP 分阶段采样直接看到面板在 window 冒泡阶段之前就没了。
- **归属**:`git log -L 237,243` 证明这段守卫来自 demo 期初始提交 `cfb8490`,**不是本期回归**;
  但本期把「点结果行能预览」做成真实可达的主路径,这个一直没生效的守卫才第一次有实际影响。
- **未修**(T6 是零产品代码改动的自查任务)。修法方向:别让守卫依赖两个监听的注册顺序 ——
  ViewerHost 消费 Esc 时 `stopPropagation()`,或 SearchDialog 在 capture 阶段先记下「本次
  keydown 开始时预览是开着的」。**建议单开一票**(并入 spec §12 债务表的话下一个可用编号是 **D44**)。

### 验收中暴露的一个真实故障(已修,根因不在产品代码)

**现象**:机主首次打开搜索,面板报「搜索服务当前不可用,请稍后重试」,
`errorDetail` 是 `Cannot read properties of undefined (reading 'agentTool')`。

**排查(按怀疑度从低到高,每步都有取证)**:
1. 后端三服务 `systemctl is-active` 全 active;直连 `POST /v1/search/agent/tool -H 'X-NimoOS-User-ID: 1'`
   拿到真数据 → **后端没挂**。
2. 共享包磁盘侧 `dist/search.js` 存在、`dist/index.js` 含 `get search()`。
3. dev server curl 交付的 `index.js` **也含** `get search()`。
4. `node_modules/.pnpm` 下只有一份 `@nimotech+nimoos-service`,完好。
5. 部署版 `/var/lib/nimoos/www/app/` 是 07-31 的、无本期代码 —— 但机主看到的是本期新文案,
   故确认在 5273 上,非开错页面。
6. 5273 监听进程 cwd = `/home/nimo/NimoTech/NimoOS-New-UI`,未与 `.sp7`(5277)/`.sp8`(5288)串线。

**根因**:`optimizeDeps.exclude` 之后 Vite 仍给包内模块 import 拼 `?v=<depHash>`,并对该类 URL 发
`Cache-Control: max-age=31536000,immutable`。而 **`depHash` 算的是依赖清单/lockfile,不是文件内容**
—— 共享包**新增一个域不会改变它**。机主浏览器在 Task 0(08-04 16:34)之前开过 5273,
把 `?v=3c9459a3` 那个 URL 的**无 search 版本**永久缓存,此后重启 dev / `pnpm build` 都不会再取。
`service.search` 恒 `undefined` → `.agentTool` 抛 → 被 `useSearchQuery` 的 catch 渲染成
「搜索服务不可用」,**外观酷似后端故障**。

**修法**:`rm -rf node_modules/.vite` 重启 dev,depHash `3c9459a3` → `e79c2def`,
URL 变了缓存自然命中不上;机主 Ctrl+Shift+R 后一次通过。**无产品代码改动。**

**流程教训(已入记忆 `nimoos-service-pnpm-drift` 第三节)**:
> §9 的四项探活里第 3 项「dev 交付的共享包 `.js` 里有 `agentTool`」**只 grep 了服务端交付的内容,
> 没看浏览器会不会去取它** —— 服务端始终正确,所以探活全绿而机主一点就炸。
> **此后凡验「dev 有没有喂新包」,必须连 `?v=` 的 `Cache-Control` 一起看**;
> 共享包新增域之后,验收前先 `rm -rf node_modules/.vite` 或 `pnpm dev --force`。
