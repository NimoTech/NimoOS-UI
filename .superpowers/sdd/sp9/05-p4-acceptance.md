# ⛔ 第一屏:这一期不要点的地方

1. **「更改密码」的提交按钮 —— 一次都不要点。**
   后端会用 `chpasswd` **写 `/etc/shadow`**(`NimoOS-UserService/route/v1/user.go:403`),而这台机器的
   SSH 登录和 Web 登录用的就是这套凭据;不知道新旧密码就改不回去,**不可撤销**。
   页面可以打开、三个输入框可以随便填、可以看不一致时的红字报错 —— **就是别按「提交」**。(债务 D26)

2. **头像的「提交」按钮 —— 默认不要点。**
   两件事:① 会往磁盘写 `/var/lib/nimoos/1/avatar.png`;② 更要紧的是后端对**解不开的图片**用了
   `log.Fatal`(`user.go:270`),会把 UserService 打死一次 → **所有人的登录立刻失效、要重新登录**
   (服务本身 `Restart=always`/100ms 会自动拉起,我实测过)。
   → 若你愿意承担「重新登录一次」这个代价,**单独告诉我一句,这一条就能关账**(债务 D27)。
   在此之前:裁剪框可以随便拖、右边圆形预览会跟着变 —— 只是别按「提交」。

3. **成员区的「+ 添加」提交、每行的 `✕`(删除);以及成员文件夹授权页的「授权」、每行的 `✕`(撤销)
   —— 都不要点。**(你 2026-08-01 已拍板 = 债务 D28)
   - 添加会真建一个 Linux 用户(`useradd`,shell `/bin/false`、无 SSH)+ 写 `/etc/shadow` + `setfacl`;
   - 删除会 `userdel` **并 `os.RemoveAll` 掉该用户的数据目录**,不可撤销;
   - 授权/撤销会真改 `/DATA` 目录的 ACL,而**文件区能看见哪些文件就是按那张表判的**。
   → 表单可以展开、可以看三条校验红字(空/密码短于 6 位/两次不一致)、可以点「取消」;
     确认弹窗**可以弹出来看**,但**别点里面那个红色的确认键**。

4. **folder-permissions 那一页整页都点不动,那是故意的。**
   政策三:界面先做、数据源等相册区(SP7)与 AI 区(SP8)合并后再接(债务 D11)。
   四个「服务离线」徽标 + 顶部那句「数据源待…合并后接入。」**是本期的正确形态,不是坏了**。
   「+ 添加文件夹」弹窗打得开,里面三个根按钮和「添加」键都是灰的 —— 也是故意的。

**可以放心点的**(全部只读,已实测无副作用):
账号卡的「更改头像」下拉菜单 · **「从NAS选择」整套浏览**(存储卡 → 目录下钻 → 面包屑 → 「上一层」→ 点图片进裁剪) ·
「更改密码」页面本身 · 成员区「+ 添加」表单的展开/校验/取消 · 每行的 `›`(进授权页)·
folder-permissions 的刷新按钮与添加弹窗 · 所有页脚的「返回」· **「退出账户」**(会退出登录,重新登录即可)。
